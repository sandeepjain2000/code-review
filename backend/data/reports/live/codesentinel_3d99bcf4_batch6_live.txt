  FILE: src/app/dashboard/student/calendar/page.js
  Score: 58/100   Issues: 5

  The component is simple and mostly safe, but has a critical runtime crash when `data` is undefined during initial load (SWR has no loading guard), causing `data.events` to throw. Additionally, the fetcher lacks a non-JSON response guard, and the calendar cell key uses array index instead of a stable identifier. The component also lacks error boundaries and loading/empty states expected in a production SaaS app.

  [CRITICAL] runtime -- Line 17
  SWR `data` is undefined during initial load (before first fetch completes). Accessing `data?.events` on line 18 will throw because `data` is undefined, not null. This crashes the entire component on mount.
  Fix: Guard against undefined data by using `data?.events ?? []` or check `!data` before accessing events.

  [HIGH] error_handling -- Line 9
  Fetcher calls `res.json()` before checking `res.ok`. If the server returns a non-JSON response (e.g., HTML error page, 502 proxy error), `res.json()` will throw a SyntaxError that is not caught, crashing the SWR fetch and leaving the component in an error state without a meaningful message.
  Fix: Check `res.ok` before parsing JSON, and handle non-JSON responses gracefully.

  [MEDIUM] best_practice -- Line 61
  Calendar cells use array index `i` as React key. When navigating months, the cells array changes length and content, causing React to unnecessarily re-render or misidentify DOM nodes. This can lead to focus loss, animation glitches, and stale event tooltips.
  Fix: Use a stable key combining month/year and day, e.g., `key={`${currentMonth.getFullYear()}-${currentMonth.getMonth()}-${day || 'empty'}-${i}`}`.

  [MEDIUM] null_check -- Line 81
  Event title `ev.title` is rendered directly without a fallback. If an event object has a missing or null `title` property, the UI will display nothing or 'null'/'undefined' as text, confusing users.
  Fix: Provide a fallback string like 'Untitled event' or skip rendering the event if title is missing.

  [LOW] performance -- Line 62
  Events are filtered on every render for each day cell using `events.filter(...)`. For months with many events (e.g., 200+), this results in O(days * events) operations per render, which can cause jank on slower devices.
  Fix: Pre-compute a map of day -> events once per month using useMemo, then look up by day index.
