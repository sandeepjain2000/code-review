  FILE: src/components/ToastProvider.js
  Score: 73/100   Issues: 5

  The ToastProvider is a simple, functional component with a few notable risks. The use of `Date.now()` for IDs can cause duplicate keys under rapid-fire toasts, leading to React rendering bugs. The `setTimeout` inside `addToast` creates a stale closure over `id` but is safe due to the functional updater; however, it does not clear the timeout on unmount, causing a memory leak and potential state update on unmounted component. The `removeToast` function is not exposed in the context value, limiting consumer flexibility. No validation is performed on the `message` or `type` parameters, which could lead to rendering issues or accessibility violations. The toast container is rendered inside the provider, which may cause layout shift and does not use a portal, risking z-index stacking issues in complex layouts. Overall, the component is adequate for light use but needs hardening for production.

  [HIGH] bug -- Line 10
  Using `Date.now()` for toast IDs can produce duplicate IDs when multiple toasts are added within the same millisecond, causing React to treat them as the same key and leading to rendering bugs (missing toasts, incorrect removal).
  Fix: Use a monotonically incrementing counter or a UUID library (e.g., `crypto.randomUUID()`) to guarantee unique IDs.

  [HIGH] memory -- Line 12
  The `setTimeout` inside `addToast` is never cleared when the component unmounts or when the toast is manually removed before the timeout fires. This causes a memory leak and a potential state update on an unmounted component, which React warns about.
  Fix: Store timeout IDs in a ref and clear them on unmount and on manual removal.

  [MEDIUM] uiux -- Line 25
  The `removeToast` function is not exposed in the context value, so consumers cannot programmatically dismiss a toast (e.g., after a navigation event or user action outside the toast close button).
  Fix: Include `removeToast` in the context value to allow consumers to dismiss toasts programmatically.

  [MEDIUM] uiux -- Line 27
  The toast container is rendered inside the provider, which may cause layout shift and z-index stacking issues in complex layouts. It should be rendered in a portal (e.g., at the document body level) to ensure it overlays all content properly.
  Fix: Use `createPortal` from 'react-dom' to render the toast container at the document body level.

  [LOW] input_validation -- Line 9
  No validation is performed on the `message` or `type` parameters. An empty message or an invalid type (e.g., 'critical') could lead to rendering issues or incorrect accessibility attributes.
  Fix: Add validation to ensure message is a non-empty string and type is one of the expected values, falling back to defaults if invalid.
