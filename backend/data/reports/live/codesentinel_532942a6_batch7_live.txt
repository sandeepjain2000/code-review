  FILE: src/app/dashboard/student/calendar/page.js
  Score: 72/100   Issues: 6

  The StudentPlacementCalendarPage component is a lightweight read-only calendar view with proper loading/error delegation via SWR. The main risks are: (1) no error or loading state is rendered when the API call fails or is pending, leading to a blank calendar with no user feedback; (2) the fetcher does not include credentials (cookies), so the API call will fail silently in production if the session cookie is not sent; (3) the calendar grid uses array index as React key, which can cause rendering bugs when navigating months; (4) no empty state is shown when there are no events, leaving users confused. The component is otherwise simple and well-structured.

  [HIGH] authentication -- Line 17
  The fetcher function on line 8-13 does not include credentials: 'include' in the fetch call. In a Next.js App Router client component, the session cookie is not automatically sent with fetch. This will cause the /api/student/calendar endpoint to receive an unauthenticated request and return a 401, resulting in a blank calendar with no user feedback.
  Fix: Add credentials: 'include' to the fetch call so the session cookie is sent with the request.

  [HIGH] uiux -- Line 17
  The component destructures only 'data' from useSWR and ignores 'error' and 'isLoading'. This means when the API is loading or fails, the user sees a blank calendar with no indication of what is happening. In production, this is a poor user experience — users will think the page is broken.
  Fix: Destructure 'error' and 'isLoading' from useSWR and render appropriate loading and error states.

  [MEDIUM] bug -- Line 61
  The calendar cells use the array index 'i' as the React key. When navigating between months, the cells array changes length and content, but React uses the index as the key, which can cause incorrect DOM reconciliation — events may appear on wrong days or fail to animate properly.
  Fix: Use a stable unique key combining the month and day, e.g. `${currentMonth.getMonth()}-${currentMonth.getFullYear()}-${day || 'empty'}-${i}`.

  [MEDIUM] edge_case -- Line 62
  The event filtering on line 63-67 creates a new Date from e.date. If e.date is an invalid date string (e.g. '2024-13-01' or 'not-a-date'), the Date constructor returns an Invalid Date, and calling getFullYear() on it will return NaN. The comparison NaN === number will always be false, so the event is silently dropped. This is acceptable but could be improved with a validation check.
  Fix: Add a check that the parsed date is valid before comparing, e.g. if (isNaN(d.getTime())) return false.

  [LOW] uiux -- Line 80
  The event title is rendered directly inside a div without any truncation or overflow handling. If an event title is very long, it will break the calendar grid layout by expanding the cell width.
  Fix: Add CSS classes like 'truncate' or 'overflow-hidden text-ellipsis whitespace-nowrap' to the calendar-event div.

  [LOW] saas_completeness -- Line 93
  The tip text references 'Browse drives' but there is no link or button to navigate to the drives page. Users have to manually find the page, which is a poor UX pattern.
  Fix: Wrap 'Browse drives' in a Next.js Link component pointing to the drives page.

The main risks are: (1) the status badge logic assumes only 'Completed' vs non-completed, which will break for other statuses like 'Scheduled', 'Cancelled', etc.; (2) the calendar view uses hardcoded initialYear/initialMonth (2026/8) which will be outdated quickly and ignores the actual interview dates; (3) the fetcher lacks a timeout, risking hanging requests; (4) no authentication check or redirect for unauthenticated users.   [MEDIUM] error_handling -- Line 7
  fetcher function has no timeout. If the API endpoint hangs (e.g., DB slow, network issue), the request will hang indefinitely, leaving the user with a perpetual loading state.

  [MEDIUM] authentication -- Line 16

  [LOW] null_check -- Line 67

  [LOW] uiux -- Line 82
