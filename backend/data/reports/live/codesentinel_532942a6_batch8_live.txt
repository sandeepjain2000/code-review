  [HIGH] bug -- Line 21
  Potential infinite re-render loop when a single image URL fails to load. The `handleError` function calls `setIdx(idx + 1)` when `idx + 1 < candidates.length`. If `candidates` has only one element (idx=0), the condition `0 + 1 < 1` is false, so it does not update state. However, if `candidates` has two or more elements and the first URL fails, it updates idx to 1, which triggers a re-render. If the second URL also fails, `handleError` is called again with idx=1, and `1 + 1 < 2` is false, so it stops. This is correct for multiple candidates. The real risk is if the component re-renders for another reason (e.g., parent re-render) while the image is still failing, the `onError` could be re-attached and fire again, but React's synthetic event system should prevent this. The more likely issue is that if `candidates` is empty (idx=0, candidates.length=0), the component renders initials, which is correct. No infinite loop is actually possible here because the state update is conditional and the condition prevents updates beyond the array length. However, the logic is fragile and could cause unexpected behavior if the component re-renders with a different `logoUrl` prop while an image is still loading.
  Fix: Add a ref to track whether the image has already errored to prevent re-attaching the error handler on re-renders, or use a more robust fallback mechanism that doesn't rely on state for error tracking.
